### Проблемы / приоритет

**P0 — перед следующим релизом:**

1. **Подмена SEO-адреса:** у live-главной и тарифных страниц canonical/og:url указывали на `https://kodbuster.github.io/KodBuster_ru_v2/`, хотя основной домен — `https://kodbuster.ru/`. В тестовой ветке исправлен default `siteRoot()` на основной домен; при production-сборке необходимо убедиться, что переменная `NEXT_PUBLIC_SITE_URL` не переопределяет его.
2. **Тестовый MAX:** опубликованная главная содержала `https://max.ru/u/test`. В тестовой ветке ссылка убрана из fallback; показывается только при установленной действительной `NEXT_PUBLIC_MAX_URL`. Настоящий MAX нельзя выдумывать.
3. **Реквизиты оператора:** `operatorReady` зависит от NEXT_PUBLIC_OPERATOR_*; значения в репозитории не заданы и privacy-страница предупреждает о неполноте. Нужно отдельно проверить фактически установленный production environment и сведения оператора до приёма заявок.
4. **Форма / PHP:** `NEXT_PUBLIC_LEAD_ENDPOINT` по умолчанию `/api/lead.php`. Прохождение UI-тестов не подтверждает доставку через Telegram/MAX. Нужна тестовая заявка в контролируемой среде, проверка PHP, endpoint, CORS, 152-ФЗ, антиспама.

**P1 — заметно влияет на конверсию и качество:**

5. Данные для доказательных кейсов не предоставлены. Портфолио содержит 5 открываемых проектов, но не подтверждает ROI и прирост клиентов. Не придумывать проценты.
6. Репозиторий хранит около 40.8 MB исходных blob-файлов, включая PNG блоков услуг от ~2 MB; на скорость влияет только реально загруженный пользователем набор. Провести image waterfall/Lighthouse и оптимизацию PNG→WebP/AVIF отдельно; не заявлять конкретную скорость по одному весу репозитория.
7. Сильно различаются страницы-примеры `/demos/*` и реальная услуга. В демо «Старт» на первом экране указаны примерные «6 лет», «600+» и телефон. Для устранения ложного впечатления в обёртке тарифа «Старт» добавлена заметная пометка, что показатели и контакты демонстрационные. В «Росте» и «Системе» такое предупреждение уже было.
8. GitHub Pages workflow на новом main ранее завершался ошибкой в configure-pages; настоящий `kodbuster.ru` при этом открывается. Не переключать хостинг вслепую; уточнить выбранный production-процесс.
