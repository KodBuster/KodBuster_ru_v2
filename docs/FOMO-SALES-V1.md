# KodBuster FOMO Sales — отдельная тестовая версия v1

**Основа:** текущая ветка main (Next.js, TypeScript, существующие компоненты, портфолио, форма).
**Рабочая ветка:** `feature/fomo-sales-v1`. Никаких изменений main, DNS, основного домена и публикации.

## Цель
Увеличить долю посетителей, которые соглашаются на предметный разбор своего бизнеса и доходят до диалога о разработке сайта. Без давления, ложного дефицита и необоснованных финансовых обещаний.

## Какие принципы навыка SALES NEXT применены
- `01-account-research`: сначала изучить реальный бизнес, не допускать выдуманных характеристик.
- `02-competitor-intelligence`: сравнивать сопоставимые компании по одинаковым открытым критериям.
- `03-owner-psychology`: ориентироваться на реальные бизнес-задачи, а не на предположения о слабостях собственника.
- `04-gap-and-fomo`: показывать разрыв между качеством бизнеса и качеством его презентации.
- `06-proposal`: предлагать честный следующий шаг (разбор) вместо давления на покупку.
- `07-quality-gate`: не обещать заявки, места, ROI, рейтинги и отзывы без подтверждения.
- `08-win-loss`: проверять эффект внедрения по конверсиям и качеству лидов.

Руководство пользователя `KODBUSTER-SALES-NEXT-v1.0.zip` не включено в публичный репозиторий автоматически: его содержимое использовано как правила разработки текстов.

## Уже реализовано
1. **Новый маршрут первого экрана** — вопрос о сравнении с конкурентами и переход в интерактив вместо немедленного давления на покупку.
2. **#compare** — переключение детайлинг / косметология / ремонт, сравнение слабого и более понятного сценария, указание, что пример учебный.
3. **#audit** — прозрачное обещание предварительного разбора; не выдумываем, что уже проверили конкретную компанию.
4. **Тарифы** — пояснение «когда выбирать» без изменения цены, состава, сроков или механики заявки в исходном коде.
5. **#economy** — калькулятор количества дополнительных заказов для покрытия цены разработки; требует прибыль с одного заказа; без прогноза ROI.
6. **CTA / форма** — заявка теперь разделяет предварительный разбор бизнеса и выбор тарифа. Добавлены необязательные поля: ниша, ссылка на сайт/Яндекс Карты, задача. Для совместимости с текущим PHP API сведения собираются в один текст комментария (максимум 1000 символов).
7. Адаптивные стили с учётом `prefers-reduced-motion`.
8. Playwright-тесты поведения, расчётов и формы запроса аудита.
9. Цели Метрики при согласии посетителя на cookie: `form_start`, `lead_submit`, `audit_form_start`, `audit_request_submit`, `package_lead_submit`. Никакие поля заявки в Метрику не передаются.
10. План пилота в `docs/FOMO-PILOT-EXPERIMENT.md`, стандарт кейсов в `docs/CASE-EVIDENCE-GATE.md`.

## Чего пока нет
- Нет персональных аудитов живых компаний: для них нужны проверенные источники и согласование использования названий.
- Нет доказанных конверсий или заявлений «до/после» об эффективности агентства.
- Нет новых лидов или измерений A/B-теста.
- Нет выкладки в интернете и отдельного предпросмотра.
- Ветка наследует конфигурацию контактов и обработки заявок из main. Убедитесь, что реальные переменные окружения, приёмник заявок и реквизиты оператора проверены перед включением формы.
- Ветка main может отличаться от версии, уже опубликованной на `kodbuster.ru`; сравните перед релизом.

## Как посмотреть локально
```bash
npm ci
cp .env.example .env.local
npm run dev
```
Откройте `http://localhost:3000`. Переменные среды в `.env.local` настраиваются самостоятельно. Без `NEXT_PUBLIC_LEAD_ENDPOINT` форма не может реально отправлять заявки, но должна корректно сообщать об этом.

## Проверки перед публикацией
```bash
npm run typecheck
npm run lint
npm run build
npm run test:e2e
```
Тесты Playwright должны выполняться в браузере; кроме них вручную проверить 360, 390, 768, 1280 и 1440 px; раскрытие мобильного меню, все CTA, отправку заявок и сценарий согласия.

## Метрики пилота
Реализованы технические цели старта формы и успешной отправки обращения, разделённые по намерению («разбор» / «тариф»). Просмотр интерактива и переход к форме пока **не измеряются отдельно**. Для оценки сделок нужна защищённая CRM вне публичного репозитория; структура и дизайн пилота описаны в `docs/FOMO-PILOT-EXPERIMENT.md`. Любая Метрика включается только после согласия на cookie.

## Условия релиза
**Не сливать в main и не публиковать без отдельного согласования.** Проверить реальные тарифы на опубликованном сайте и привести код в соответствие до выпуска.
